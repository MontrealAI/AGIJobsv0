              YOUR FIRST COMPLETE RUN

              From assumptions to a reviewable result

              1. Read the model. Inspect this profile’s config files. Recorded dates identify fixtures; they are not freshness claims.
              2. Reproduce it. From the repository root, run nvm install, nvm use, npm ci, then npm run demo:kardashev-ii-stellar:orchestrate.
              3. Verify it. Run npm run demo:kardashev-ii-stellar:orchestrate -- --check. This compares artifacts and enforces critical/high readiness checks without writing files.
              4. Experiment. Copy the profile configuration, change one input, and select separate --config-root and --output-dir directories. Compare the ledger warnings and metrics. A stressed model can intentionally fail readiness.

              Read the evidence correctly. Input hashes establish reproducibility. Encoded calls and owner-selector checks establish proposal structure, not authority, signatures or successful transactions. Safe batches contain placeholder targets and are not ready to submit.

              Units. GW measures power; GWh measures stored energy; EF means exaflops. Currency values are scenario assumptions. Thermostat “Kelvin” fields are legacy normalized model parameters, not measured stellar temperatures.
