## Storage credential migration

Only these **Node release publishers** change:

- `apps/onebox/scripts/publish.mjs`
- `apps/onebox-static/scripts/publish.mjs`
- `scripts/onebox-static/release.mjs`

The shared adapter is `scripts/lib/w3up-upload.mjs`. The first two publishers retain their packing commands, skip flags, Pinata and ENS behavior. The third now packs its directory into a CAR before invoking the same adapter. It does not promise the same root as every historical legacy-SDK directory packing configuration: review the generated root before publishing a new release. Historical CIDs, ENS records and release history are not rewritten.

Provide these values only to the trusted release process:

| Variable         | Meaning                                                                                                                     |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `W3UP_KEY`       | Serialized Ed25519 upload-agent key. **Not an Ethereum private key or wallet seed.**                                        |
| `W3UP_PROOF`     | Base64 delegation archive for that agent, with authority over the selected space and required blob/store/upload operations. |
| `W3UP_SPACE_DID` | Explicit provisioned `did:key:...` upload space.                                                                            |

The authorized space administrator must provision the space and delegate the required upload/index-read authority to the dedicated agent. Use expiring, least-privilege authority where the provider supports it; the wildcard delegation in unit tests is an offline fixture, not a recommended production policy. Keep the principal and delegation private. The adapter uses an in-memory store; it does not log in interactively, persist credentials, create a space, purchase storage or fall back to legacy bearer tokens.

`WEB3_STORAGE_TOKEN` and `W3S_TOKEN` no longer authenticate these publishers. Existing ENS/Pinata credentials and their explicit write behavior are unchanged. This PR never requests or exercises them. Do not run a publishing command merely to test dependency installation.

The adapter checks the proof audience, time bounds and selected space locally. That is not independent verification of the entire delegated authorization chain: the provider must validate the signed capability during each operation. Authentication parsing alone does not prove storage allocation, billing or remote access.

The two `apps/.../scripts/publish.mjs --dry-run` routes remain suitable for local packaging inspection with no upload or ENS write. The older `scripts/onebox-static/release.mjs` command is a live publisher without a dry-run flag; do not execute it with real secrets during qualification.

## CAR and result semantics

The adapter accepts a nonempty single-root CAR (maximum 256 MiB), verifies its root against the caller's expected CID, sends those exact bytes, checks the returned CID, then requires an upload-index record for the same root with valid shard CIDs. Missing credentials, invalid CAR/root, upload errors, mismatched roots and failed/malformed readback stop before subsequent publisher ENS/configuration output.

`status.confirmation` is `upload-index-readback` and `status.storageDealsVerified` is `false`. An index record is not proof of replication, storage deals, indefinite availability or successful retrieval of every block. Keep separate Pinata and gateway checks. Legacy metadata fields remain present where used, but unknown pin/deal/dag-size fields stay null/empty rather than being fabricated. New upload-index evidence is preserved alongside them.

An upload may have reached the service before an error or readback failure. Do not blindly retry or claim rollback; inspect the root's remote state with the authorized provider first. SDK-internal transport retry behavior is not a repository deployment journal. The adapter adds no automatic retry of the release/ENS sequence.

The browser's legacy bearer-token uploader and orchestrator HTTP-pinner defaults are **not migrated by removal of the Node SDK**. They do not import that package, but may still target discontinued provider endpoints. Their separate provider migration/commissioning remains necessary before claiming those surfaces work live. No Storacha signing key is put in browser configuration.

## Qualification commands

Use a separate development checkout, not the operator's preserved rc.3 directory. Retain the baseline install and its audit evidence.

```bash
npm run ci:preflight
npm ci
npm run test:dependency-compat
node scripts/security/verify-braces-patch.cjs
node --test attestation/eas/test/receipt-digest.test.mjs
npm run sbom:generate
node scripts/security/check-dependency-preservation.cjs source
npm run compile
npm run release:check-size
npm run deploy:local
node scripts/security/check-dependency-preservation.cjs generated
```

`deploy:local` is the unchanged in-process Hardhat rehearsal, not a public-network deployment. No remote RPC or real-wallet key is used. Compiler-generated configuration changes in the disposable checkout are compared against running the unchanged baseline generator with the same dependencies. They are not committed into the PR or silently treated as new deployment settings.

Run both audit views and the existing all-lockfile release gate. Any new high/critical finding or unavailable evidence remains a failure; do not ignore it with `|| true`:

```bash
npm audit --package-lock-only --ignore-scripts --include=dev --include=optional --include=peer --json --audit-level=high
npm audit --package-lock-only --ignore-scripts --omit=dev --json --audit-level=high
npm run release:audit-dependencies
```

The read-only `Dependency repair qualification` workflow preserves exact head/version metadata, individual exit codes, full logs and audit JSON. It has no repository-write permission and cannot commit generated files or use deployment/provider secrets. It supplements, rather than replaces, the existing CI/browser/release gates. The temporary branch-writing resolver is removed from the final diff.

Compatibility positives use real installed libraries and local CAR files, real offline signed delegation fixtures, and a mocked upload service for success/failure shapes. Publisher entrypoint tests execute the actual commands in disposable fixture trees with networking blocked. These do not prove a paid provider account is provisioned or an external upload is live-qualified. Review the final test matrix before any merge or deployment decision.
