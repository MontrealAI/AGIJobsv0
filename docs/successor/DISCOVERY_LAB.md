## Receiver resource reservation and failed attempts

Before calling the installed semantic checker, the receiver charges 10,000 declared admission checking units and counts the encoded raw input, parsed/canonical/frozen copies and expected-context copies. Memory byte units describe those encoded data footprints, not JavaScript heap measurements. It reserves a conservative `2 * inputBytes + 131072` bytes for the complete receipt, including escaped reasons, then supplies only the remaining resource vector to the checker. Insufficient reservation stops before semantic work and remains inconclusive. Actual receipt bytes and checker costs are retained; elapsed milliseconds are measured without charging native wall time twice.

Rejected context and other thrown failures retain their current receiver resource charge. If the installed inspector throws without a valid usage report, the native reservation remains explicitly unresolved; it must not be treated as zero-cost work or a completed negative result. Transport-policy doubles are not performance measurements.

Candidate-only CI derives the complete source path list independently from the actual Git index, refuses untracked source, checks every current byte/mode, and records the exact head/tree. The source-profile test also stages a real directory and verifies that an added rogue file fails default actual-directory enumeration. Package acceptance must enumerate the complete extracted/archive source; it must never supply the verifier's expected set as the observed inventory.

The frozen remaining native allowance is checked independently of the final total cap: unused conservative receipt reservation cannot retroactively enlarge checker memory or storage. All aggregate additions use exact integers before conversion; an unrepresentable total refuses admission while preserving safe receiver/checker components and exact decimal totals. Unsupported/unprovisioned probes and malformed requests retain current admission charges too.
