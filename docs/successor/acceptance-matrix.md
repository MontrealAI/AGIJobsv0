## How to read the record

- **PENDING**: required behavior has not yet been checked against named implementation and test evidence.
- **LOCAL**: a named local test passed; its scope does not establish independent proof or production operation.
- **PARTIAL**: local evidence covers only part of the requirement; the missing part remains explicit.
- **BLOCKED**: a required check failed or could not run. It remains a gate.
- **EXTERNAL**: independent custody, production credentials, real worker/network commissioning or accountable admission is required.

Record commands, environment and exit status in the release dossier, alongside the generated checkout revision, working-tree state and source digest. The release PR identifies the final head. A passing fixture test cannot change EXTERNAL to independently evaluated. Do not infer completion from a file, function name, documentation or successful website deployment. When a row has multiple obligations, do not mark the whole row LOCAL unless all local obligations are exercised.

## Separate commissioning gates

The local release cannot supply an independent examiner, protected real cases, trusted maintainer or evaluator keys, organizational authorization, provider accounts, professional authority or a deployed worker's actual controls. Track these as separately owned evidence objects with review dates, never fixture substitutes. Existing [production readiness](../production/readiness.md) gates remain in force, including dependency/security review, signing trust, network configuration, validator recovery and provider migration.

Each release report must identify what runs, what was measured, negative findings, unrun/failed checks, exact commit and remaining external actions. A rejected challenger is a valid mission outcome; an incomplete required test is not a passing release gate.

## Validation evidence

Source/test paths in this matrix are relative to `packages/successor-core/` unless explicitly stated. Use Node **22.23.3**, npm **10.8.2** and locked dependencies. The generated release report's `checkout.revision`, working-tree state and `sourceDigest` identify what ran; the release dossier supplies exact commands, exits and final PR head. Intermediate working-tree counts are not a final release certificate and must not be added across overlapping suites.

| Existing contract, size, documentation, site and diagram gates | Repository compatibility and exact built-asset checks; separate from independent examination or commissioning |

SEIZE records are unsigned commitments: ELEVATE references a candidate digest and grants no authority. The examination adapter separately verifies the complete frozen system. Domain role identifiers do not authenticate a caller. Public export verifies supported fixture identity, source bytes, seals and recomputed results; it rejects customer content or altered metrics relabeled as a public fixture.

Comparison intervals are separate one-sided bounds; the lower bound drives the advantage decision, with no joint two-sided confidence claim. The WORLD fixture explicitly records that independent empirical sampling and real deployment cost are unestablished. Its source commitment and local fixture signature do not authenticate historical execution or external provenance.

Store/pack and institution checks cover real compiled dependencies, fresh-lease denial after source revocation, clean-directory CLI restore, symlink state paths, malformed knowledge expiry, known credential aliases and modified lineage. Live worker isolation, independent custody and production authorization remain outside this local evidence.
