# SUCCESSOR Ω acceptance and evidence matrix

This matrix was recorded before implementation of the final proof path. Source baseline: `5b4cebb309a83a7a6749d8911d8bf96a1921e042`, published as [source-v2.0.0-baseline.1](https://github.com/MontrealAI/AGIJobsv0/releases/tag/source-v2.0.0-baseline.1). A source release is not a production admission.

The release mandate is **α-AGI Ascension → SUCCESSOR Ω**: bounded work, executable discovery, honest comparison and portable knowledge, with independently controlled proof and authority. IDs below preserve the mandate's acceptance cases. Implementation coverage and achieved evidence are separate.

## How to read the record

- **PENDING**: required behavior has not yet been checked against named implementation and test evidence.
- **LOCAL**: a named local test passed; its scope does not establish independent proof or production operation.
- **PARTIAL**: local evidence covers only part of the requirement; the missing part remains explicit.
- **BLOCKED**: a required check failed or could not run. It remains a gate.
- **EXTERNAL**: independent custody, production credentials, real worker/network commissioning or accountable admission is required.

Record commands, environment, exit status and final candidate SHA in the release dossier. A passing fixture test cannot change EXTERNAL to independently evaluated. Do not infer completion from a file, function name, documentation or successful website deployment. When a row has multiple obligations, do not mark the whole row LOCAL unless all local obligations are exercised.

## Separate commissioning gates

The local release cannot supply an independent examiner, protected real cases, trusted maintainer or evaluator keys, organizational authorization, provider accounts, professional authority or a deployed worker's actual controls. Track these as separately owned evidence objects with review dates, never fixture substitutes. Existing [production readiness](../production/readiness.md) gates remain in force, including dependency/security review, signing trust, network configuration, validator recovery and provider migration.

Each release report must identify what runs, what was measured, negative findings, unrun/failed checks, exact commit and remaining external actions. A rejected challenger is a valid mission outcome; an incomplete required test is not a passing release gate.
